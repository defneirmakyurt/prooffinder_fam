## Agreement matrix (`pp.py matrix`)
7. **Classification on real verdicts is right where it matters.** Sequence observed:
   - After 2B tasks existed, before any cross-verifier: **UNSUPPORTED**, with an empty table and the reason "every
     verdict is in" — although both 2B solvers had not even been dispatched. Wrong label: nothing was in. It should
     be INCOMPLETE. Cause: `compute_matrix` builds rows only from 2B tasks that *already have* `proof.md` plus
     cross-verifier subjects; a running 2B solver is not a row, so nothing is "pending".
     → **PROPOSED:** count a 2B task with no `done` event as pending (row "solver running"), and return INCOMPLETE
     instead of UNSUPPORTED on an empty matrix.
   - Cross-verifiers dispatched, pending: **INCOMPLETE** ("verdicts are still pending on A-C2-002"). Correct.
   - 012 + 013 CONFIRMED on 002: **ROBUST** via 002, with 010 and 011 shown as rows with pending verdicts. Correct: ROBUST
     is a per-proof property and the pending rows are listed under "Pending".
   - 014 ACCEPT + 016 CONFIRMED on 011: **ROBUST via 002 and 011**. Correct.
   CONTESTED was never exercised: every verdict on real proofs was positive. It still has synthetic coverage only.
8. **ACCEPTed Phase 1 / 1L proofs are invisible to the matrix unless someone cross-verifies them.** 001 and 003 both
   passed Phase 2 and never appear, not even as "pending". The skill says every ACCEPTed proof gets cross-verifiers;
   the matrix doesn't flag the ones that didn't. → **PROPOSED:** include every proof with a Phase 2 ACCEPT as a row.
9. **Cost asymmetry the budget formula misses.** A Phase 1/1L proof has no own branch, so ROBUST needs a
   cross-verifier from *every* kept branch (2 here); a 2B proof needs one fewer (1 here). The skill's budget line
   "(proofs that passed Phase 2) × (kept branches − 1)" undercounts Phase 1 proofs by one call each. With two kept
   branches, 011 became ROBUST on two verdicts in total (one verifier, one cross-verifier).

    - 002 right after 2B tasks were created: **GAP** — "matrix is UNSUPPORTED, not ROBUST".
    - 002 after 012/013 CONFIRMED: VALID again (matrix ROBUST, this proof robust).
    - 011 (ROBUST, one ACCEPT): **GAP** — "1 counted ACCEPT(s) of 2 needed". ROBUST does not stand in for the second referee.

11. **Running 2B on an already-gated cell flips its gate from VALID to GAP**, and stays GAP until every cross-verifier
    on that proof returns. The board kept saying PROVED throughout, because the board is written by the head, not by the
    gate. For ~4 minutes (12:28–12:32) the ledger held a VALID board row and a GAP gate report for the same proof. Harmless here;
    on a real run a checkpoint taken in that window would report a SOLVED cell whose latest gate says GAP.
    → **PROPOSED:** either the skill says "don't start 2B on a gated cell", or `pp.py gate` records the earlier
    VALID in the report ("previous decision: VALID at hh:mm, before 2B") instead of silently replacing it.
12. **Every `pp.py gate` call overwrites both `gate_report.md` and `gate/<task>.md`, and logs a `gate` telemetry
    event.** There is no dry-run. Probing the gate on 001 and 011 left GAP reports for proofs nobody was gating, and
    the earlier VALID for 002 survives only because the head copied it by hand.
    → **PROPOSED:** `--dry-run`, or never overwrite `gate/<task>.md` (append a timestamped file).
13. Tooling refusals worked on real input: a second ANALYSIS cross-verifier on 002 ("never cross-verify twice from

## Isolation
14. **Near-breach, caught before dispatch: 2A/2C obstacles leak Part S and whole proofs into BLIND inboxes.**
    `pp.py task --phase 2A --obstacles T…` copies each named task's `verdict.md`. Per protocol an ACCEPT verdict
    gives every Part S line with a reason (S2 named the equality tuple `(e_1, e_1, e_2, …)`, S4 the R^m trap) and
    per-step reasons that amount to a proof sketch ("cofactor expansion along last row… D_k = D_{k-1} − a²D_{k-2}").
    A-C2-007 was built this way for the blind triage agent, the head read its inbox, and did **not** dispatch it;
    A-C2-008 was rebuilt with the provers' `stuck.md` only. 2C (A-C2-015) was given `stuck.md`-only obstacles for
    the same reason. The skill and the triage/breaker cores both say verdicts are obstacles; on a failed proof a
    MAJOR verdict carries the same Part S lines.
    → **PROPOSED (needs a human decision):** have `--obstacles` copy from `verdict.md` only the VERDICT /
    FIRST PROBLEM / RED FLAGS lines (never CHECKLIST), and skip ACCEPT/CONFIRMED verdicts entirely; add a test
    asserting no `S[1-9] ` line reaches a BLIND inbox.
15. **Part S also reaches Phase 3.** `--earlier` copies every referee verdict whole into the literature analyst's
    inbox. Phase 3 is not blind and never feeds blind agents, but the skill says Part S goes to referees only. Same
    filter would fix it.
16. **There is no way to withdraw a created task.** A-C2-007 stays in `phases.md`, counts as a 2A task in
    `pp.py telemetry` ("Tasks 2, Returned 1") and is listed forever by `pp.py status` as "no 'pp.py done'
    recorded". → **PROPOSED:** `pp.py cancel TASK --reason …` writing a `cancel` event.
17. The triage agent volunteered that it "vaguely recognises a lemma of this shape in the literature", said it
    played no part, and cited nothing. That is exactly what its core asks it to report. `blindcheck`: 0 hits.

## 2B cross-verifiers (CROSS mode)
24. **CROSS mode translates, not merely re-verifies.** All three verdicts restate the key idea in their branch:
    - 012 (ALGEBRAIC on 002): the projection step *is* a Schur complement at pivot (m,m) plus a diagonal rescaling;
      rank additivity gives rank(G/G_mm) = rank G − 1, "which uses the dimension hypothesis".
    - 013 (ANALYSIS on 002): Σ arcsin|c_i| is a potential function that the elimination step never raises;
      identified the degenerate pivot cos a_{m−1} = 0 as where a naive reading would divide by zero, and checked the
      proof splits it off.
    - 016 (ALGEBRAIC on 011): re-derived 011's weighted splitting independently as an LDLᵀ pivot bound
      p_k ≥ cos²(B_{k−1}) via the continuant recursion.
    Each also re-ran the full checklist and its own exact/ball-arithmetic counterexample search (11 200 – 85 820
    admissible chains). No RED FLAGS were raised, so the "step that resists translation" signal was never tested.
